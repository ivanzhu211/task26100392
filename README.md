# MDR 告警关联组件

将乱序到达的告警归并为安全事件。纯内存、串行调用、无过期删除。
只接收告警，不含规则执行、事件处置与用户管理。

## 关联语义的形式化

同一关联分区（tenant_id, endpoint_id, correlation_key）内，把告警按
`(occurred_at, alert_id)` 排序。称排序后相邻的两条告警 `a, b` **相邻链接**，
当且仅当存在包含两者的有效证据组（三条不同告警、最大最小时间差 ≤ 600000ms）。
这等价于：`prev(a), a, b` 或 `a, b, next(b)` 落入同一窗口——因为包含 `a, b`
的第三个告警离得越近跨度越小，只需检查这两个最近的三元组。

- 任意有效证据组 `[lo..hi]` 会链接其覆盖范围内的每一对相邻告警，
  因此"共组关系"的连通分量完全由相邻链接决定，无需枚举三元组或告警对。
- 每条链接都由某个三元组见证，故链接必然把第三条告警拖入同一分量：
  分量大小只会是 1 或 ≥ 3，**事件恰好是大小 ≥ 3 的连通分量**。
- 插入只增不减：新告警落在旧相邻对之间时，只会缩短相关三元组跨度，
  旧链接永不失效。因此用并查集维护分量即可，事件只会合并、不会分裂，
  与到达顺序无关——最终划分只取决于告警集合本身。

## 数据结构

- 每个关联分区一棵 **treap**（随机平衡 BST），键 `(occurred_at, alert_id)`，
  支持 O(log n) 期望插入与前驱/后继查询。
- 每条告警是一个**并查集**元素（路径压缩 + 按成员数合并），
  根上维护事件聚合：最小 alert_id（事件 ID）、成员数、最早/最晚时间、
  成员切片（合并时小并大）。
- 每租户一张 `alert_id -> 节点` 哈希表，用于去重与 `Locate`。

## 插入流程（Add）

1. 租户内按 alert_id 去重，重复投递直接返回当前摘要。
2. 在所属分区的 treap 中插入新节点。
3. 插入只会改变至多 4 对相邻告警的链接条件：新对 `(pred, x)`、`(x, succ)`，
   以及 `(pred(pred), pred)`（其 nextB 变为 x）和 `(succ, succ(succ))`
   （其 prevA 变为 x）。逐对评估，命中即 union。
4. 返回新告警所在分量的摘要（分量 < 3 人时返回空）。

## 复杂度

设 N 为不同告警总数：

- `Add`：1 次 treap 插入 + 常数次前驱/后继查询 + 常数次并查集操作，
  期望摊还 **O(log N)**。不重新排序、不扫描整个分区。
- `Locate`：哈希表查找 + 路径压缩 find，摊还 **O(α(N))**。
- `Members`：直接取所属根的成员切片并排序，**O(k log k)**，
  不触碰其他事件或未关联告警。
- 事件合并：并查集按大小合并，成员切片小并大，
  全部合并的总代价 O(N log N)，单次合并不改写大事件的全部成员
  （10 万 + 10 万成员的单条迟到告警归并实测约 165µs，见规模测试）。
- 存储：每条告警常数个指针/字段，根上每成员一个切片元素，总计 **O(N)**；
  不保存任何三元组或告警对。

## 测试

`go test ./...`：

- `correlator_test.go`：0/60/120s 与 720/780/840s 两个事件，
  420s 迟到告警经 120s..720s = 600000ms 边界归并，旧成员查询立即更新；
  50 组随机打乱到达顺序结果不变。
- `reference_test.go`：小规模随机数据在每个插入前缀上与
  O(n³) 枚举三元组的参考实现逐条核对，覆盖重复投递、同时间告警、
  跨租户/端点/威胁类别、600000ms 边界。
- `scale_test.go`：20 万条告警逆序（约 114ms）与随机序（约 326ms）插入，
  最终划分与事件 ID 完全一致；两个 10 万成员事件被单条迟到告警归并，
  验证不会退化为整组扫描。
