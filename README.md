# task26100392 — MDR 告警关联组件

Go 实现的 MDR 平台告警关联组件：将乱序到达的告警实时归并为安全事件。
仅接收告警，不含规则执行、事件处置、用户管理；串行调用、数据驻留内存、无过期删除。

## 归并语义的结构化刻画

将同一关联分区 `(tenant_id, endpoint_id, correlation_key)` 内的告警按
`(occurred_at, alert_id)` 排序。对相邻告警间隙 `(a, b)`，定义其**链接**当且仅当
存在一个有效证据组（时间跨度 ≤ 600000ms 的三条不同告警）跨越该间隙
（最小时间 ≤ `a`，最大时间 ≥ `b`）。该条件可证明等价于：

- `a` 的前驱存在且 `b.time - prev(a).time ≤ 600000`，或
- `b` 的后继存在且 `next(b).time - a.time ≤ 600000`

即间隙链接状态只取决于两侧各两条告警。进一步可证明：

- 证据组共享关系的传递闭包（安全事件）恰好是**极大连续链接段**；
- 链接段长度必 ≥ 3，未链接孤点即未关联告警；
- 插入只会使间隙由未链接变为链接，永不反向（单调性），故可用并查集维护事件，
  迟到告警天然支持创建、扩大与合并事件，且任意到达顺序得到相同结果。

## 数据结构与复杂度

设 `N` 为不同告警总数：

- 每个分区一棵 **treap**（优先级由 `(tenant_id, alert_id)` 哈希决定，与到达顺序无关），
  配合有序双向链表：插入期望 `O(log N)`，前驱/后继 `O(1)`；
- 每次插入只重估插入点前后 **O(1) 个间隙**（新间隙两个 + 受前驱/后继变化影响的两个），
  不扫描整个分区、不重新排序；
- **并查集**（路径压缩 + 按大小合并）维护事件归属，根上 `O(1)` 维护
  事件 ID（字典序最小 alert_id）、成员数、最早/最晚时间；
  成员用单向链表头尾拼接，合并 `O(1)`，**不逐个改写旧成员**；
  历史成员经 `find` 路径压缩立即指向归并结果；
- `Add` / `Locate`：期望摊还 `O(log N)` / `O(α(N))`；
- `Members`：沿根节点成员链表取 `k` 条后排序，`O(k log k)`，不触及其他事件；
- 总存储 `O(N)`：不保存任何三元组或告警对。

## 测试

```sh
go test ./...
```

- `correlator_test.go`：0/60/120s 与 720/780/840s 两组三告警各自成事件，
  420s 迟到告警（与两侧构成跨度恰 600000ms 的证据组）将两事件合并，
  旧成员查询立即更新；50 种随机顺序 + 逆序结果不变；
- `reference_test.go`：小规模随机数据在每个插入前缀上与直接按定义
  （枚举全部有效三元组求传递闭包）的参考实现核对，覆盖重复投递、
  同时间告警、跨分区数据与 600000ms 边界（含 600001ms 反例）；
- `scale_test.go`：可重复的 20 万条逆序 / 随机（固定种子）插入，
  以及两个各 10 万条的大事件被单条迟到告警桥接归并。
